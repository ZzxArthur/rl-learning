回报(G_t):  从哪一步开始累加奖励：从当前步开始，累加到未来
马尔可夫性质:   当前状态是否已经包含预测下一步所需的信息

Q-learning 自己从下一状态取最大 Q 值，不需要知道实际选了哪个动作。
SARSA 必须知道下一动作，才能查询 Q(next_state, next_action)。

V 和 Q 是价值评估；根据 Q 取最大值，或根据 V 和环境模型比较动作，可以导出策略。策略本身则是“状态 → 动作”或“状态 → 动作概率”的规则。


基础 REINFORCE 是 on-policy：用当前策略采集轨迹，再用这些数据更新策略。

因果关系的方向需要调整一下：当前动作可以影响未来奖励，但不能改变已经发生的奖励。 因此，当前时刻的回报 \(G_t\) 应该包含当前及未来的奖励，而不包含过去的奖励：




让什么最大 就把什么作为损失值的负数即可

| | 整局采样回报（MC） | 一步 TD |
| --- | --- | --- |
| **主要优点** | 用实际发生的后续奖励，不依赖价值模型预测后半段 | 走完一步就能学习；用价值预测，通常能减少单次目标的波动 |
| **主要缺点** | 通常要等一局结束；结果受整局随机过程影响，可能波动较大 | 目标依赖价值模型；模型预测不准时，误差会影响学习 |
| **适合的直觉** | “等事情做完，看实际结果” | “先做一步，根据当前结果和后续预测调整” |



基于baseline的reinforce算法:
更新策略模型：需要每一步有正负的 TD 误差，直接相减：
policy_loss = -torch.mean(action_log_probs * td_errors)
更新价值模型：仍然需要 MSE。重新计算带梯度的当前状态价值，再与固定的 TD 目标比较：
values = value_model(states).squeeze(-1)
value_loss = torch.nn.functional.mse_loss(values, td_targets)
所以是两个模型使用同一批 TD 目标，但用途不同：策略需要逐步误差的正负来决定更新方向；价值模型需要最小化预测与目标之间的平方误差。
因为它们要改变的东西不同：
- 策略模型要调整的是“这个状态下，选择各动作的概率”。
- 价值模型要调整的是“这个状态的价值预测是多少”。
所以两者需要从 TD 误差中获取的信息不同。
策略模型：需要知道方向
价值模型：需要让预测接近目标

MC：用整局实际奖励算 returns，再用 returns 学习
一步 TD：用当前 reward + 下一状态的价值预测作目标



REINFORCE：直接学习策略（Policy-Based），让神经网络学会如何选择动作。
SARSA：学习动作价值函数（Value-Based），通过 TD 更新当前状态下动作的价值。
Q-learning：也是学习动作价值函数，但使用最优动作价值进行更新。


| 基线 | Actor 的权重 | 特点 |
| --- | --- | --- |
| 不使用基线 | \(G_t\) | 最直接，但梯度波动可能较大 |
| 固定常数 \(b\) | \(G_t-b\) | 简单，例如你在 `pra51`、`pra52` 中用过固定基线 |
| 状态价值 \(V(s_t)\) | \(G_t-V(s_t)\) | 基线随状态变化，能够反映不同状态下不同的预期回报 |
| 状态价值配合一步 TD | \(r_t+\gamma V(s_{t+1})-V(s_t)\) | 用 TD 目标估计后续回报，是当前 `pra59` 的做法 |



λ 决定的是：计算当前时刻的 GAE 时，后面各步的 TD 误差有多大影响。
λ 较小：更接近一步 TD，更早依赖 Critic 对后续价值的预测；通常采样波动较小，但 Critic 预测不准可能带来偏差。
λ 较大：更多利用后续轨迹信息；对于正常终止的完整轨迹，λ=1 时等于折扣回报减当前状态价值。它对中间状态价值预测的依赖较少，但完整回报的采样波动可能较大。


在强化学习（Reinforcement Learning，RL）中，Batch Size（批大小）指的是模型进行一次参数更新时，使用多少条训练样本。

所以旧数据有用，不是因为它代表了当前策略会怎么做，而是因为它记录了某个状态下执行某个动作后，环境实际给出的反馈。

| Transformer | 较长序列或多种信息之间的关系 | 状态、动作历史或视觉信息的组合 |

在 torch.distributions.Normal 中：
- loc 是均值 μ：分布的中心，采样通常围绕这个数。
- scale 是标准差 σ：控制采样的分散程度，必须大于0。注意它是标准差，不是方差。
例如：
distribution = torch.distributions.Normal(
    loc=torch.tensor([0.8]),
    scale=torch.tensor([0.3]),
)
表示均值为 0.8、标准差为 0.3 的正态分布。约68%的样本落在：
0.8 ± 0.3，也就是 [0.5, 1.1]
这个区间不是硬边界，仍可能采到区间外的值。


sac:
为什么不用同一个网络（自举死循环）？
在训练 Critic 时，你是在拿 q1(s_next) 算出来的分数当标准答案（靶子），
去纠正 q1(s) 的当前猜测。如果它俩用同一套参数，你刚一更新参数，猜得更准了一点，
结果标准答案自己也跟着变了——就像一边射箭靶子一边瞬移，模型很容易在来回追逐中震荡发散。

no_grad() 为什么不够？with torch.no_grad(): 只是告诉 PyTorch“这一步算梯度时别顺带修改靶子”，
但一旦执行 optimizer.step()，在线网络的参数还是变了。所以下一轮迭代再算靶子时，它依然发生了剧烈跳变。

目标网络（target_q）到底干了啥？
它就是在线网络的一个“慢动作影子副本”。每次训练只更新在线网络 q1，
而 target_q1 只通过软更新（tau = 0.005）极其缓慢地向 q1 靠拢一点点。
这样靶子在一段时间内几乎是静止的，在线网络就能安安稳稳地收敛过去。

对比维度,ϵ-greedy（如 DQN）,SAC 最大熵探索（- alpha * log_prob）
探索的聪明程度,盲目均匀随机： 触发探索时完全闭眼乱选，哪怕某个动作会立刻导致任务失败，也和好动作有同样的概率被选中。,看局势、有针对性地探索： 策略输出由状态决定的 mean 和 std。在容错率高的状态，std 会自动变大去多尝试；在关键时刻（如摆锤快立稳时），std 会自动缩小以保证精准控制。
与 Q 值的关系,"互不干扰的外挂： 算 TD Target 时依然用纯贪婪的 maxQ(s′,a′)，探索只是收集数据时的临时行为。",直接写进 TD Target： 把 −αlogπ 算进未来总价值里。智能体不仅喜欢高分状态，还会偏好那些“后续选择余地大、不容易走入死胡同”的状态。
探索幅度如何调节,靠人工死板衰减： 必须手动设定 ϵ 从 1.0 随步数线性降到 0.05，降快了容易卡死，降慢了不收敛。,按状态自适应调节： 网络自己决定不同状态下 std 该多大（配合自动调温 α 甚至连温度系数都不用手调）。
适用动作空间,主要用于离散动作（如上下左右几个按钮，因为连续空间没法直接求 maxa​Q）。,原生适配连续动作空间（如 Pendulum 的连续力矩、机械臂关节力矩）。


# 为什么需要-next_log_probs, 是本次抽样对策略熵的估计，取样本期望才是策略熵。
每次输入状态，你的网络确实会重新创建一个正态分布，但这个分布的胖瘦是由网络输出的标准差 `std` 决定的：


# 自动调整alpha的好处
- **情况 A：策略很死板（总抽几乎一样的力矩 $\rightarrow$ `std` 很小）** 既然动作都挤在极窄的区间里，为了保证曲线总面积等于 `1`，这条钟形曲线就必须变得**极其高瘦**。
  - 此时你只要随便抽 **1 次**，几乎必定落在尖峰附近，这里的概率密度非常大（比如 $p(a) = 10$）。
  - 代入公式一算：$-\log(10) \approx \mathbf{-2.3}$（**奖励很低，甚至是负数惩罚**）。
- **情况 B：策略爱探索（尝试多种力矩 $\rightarrow$ `std` 很大）** 动作分散在很宽的区间里，总面积依然是 `1`，曲线就只能变得**又矮又胖**。
  - 此时你同样只抽 **1 次**，无论抽到哪，那里的概率密度都很小（比如 $p(a) = 0.2$）。
  - 代入公式一算：$-\log(0.2) \approx \mathbf{+1.6}$（**奖励很高**）。

所以，分布不用“回顾历史”，**单次抽样点的纵坐标高度（概率密度）本身就已经包含了分布宽度的全部信息**。

| --- | ---: | ---: |
| 平均评估奖励 | −203.13 | **−176.64** |
| 评估奖励中位数 | −224.11 | **−129.16** |
| 最低评估奖励 | −465.52 | −444.52 |
| 最高评估奖励 | −3.04 | −0.10 |
| 最后 10 局训练平均奖励 | −172.34 | −146.98 |
| 训练耗时 | 133.0 秒 | 132.3 秒 |





mean 是高斯分布的中心，由 Actor 根据状态输出。
std 是标准差，控制采样的分散程度。你的 Actor 先输出 log_std，再通过 exp() 得到 std。
随机扰动是在每次采样时产生的随机数。`std` 决定这个扰动对动作的影响有多大。
u = mean + std * c

再用 tanh 把 u 限制到环境需要的动作范围。

熵用来衡量一个概率分布的不确定程度。直观地看：
动作大多集中在很窄的范围 → 熵较低
动作分布在较宽的范围     → 熵通常较高

熵有助于维持探索，降低策略过早集中到某种动作附近的可能性。

| | 确定性策略 | 随机策略 |
| --- | --- | --- |
| Actor 输出 | 当前状态对应的一个动作 | 当前状态对应的动作分布 |
| 同一状态再次输入 | 参数不变时输出相同动作 | 可以采样出不同动作 |
| 代表算法 | DDPG、TD3 | SAC、PPO |
| 训练时探索 | 常在输出动作上另外加噪声 | 可以从策略分布采样 |
